## 【言語普遍層】どの言語にも存在する概念

| レベル | 概念 | Rust での書き方 | JS との差分 | 普遍 / 固有 |
|---|---|---|---|---|
| L0 | 字句（トークン） | | | |
| L1 | 値と型（プリミティブ） | | | |
| L2 | 式（Expression） | | | |
| L3 | 文と制御フロー | | | |
| L4 | 束縛とスコープ | | | |
| L5 | 関数と抽象化 | | | |
| L6 | データ構造 | | | |
| L7 | 名前空間・モジュール | | | |

記入のヒント（調べる観点）:

- L1: 整数型の幅（`i32` / `u64` / `usize`）、`char` が 4 バイトである理由、`&str` と `String` の違い
- L2: Rust では `if` / `match` / ブロックが**式**である（JS は文）
- L4: `let` の shadowing、`mut` の有無、ブロックスコープと所有権の関係
- L5: クロージャの 3 種（`Fn` / `FnMut` / `FnOnce`）
- L6: `Vec` / 配列 / スライス / `HashMap` / `struct` / `enum` / タプル
- L7: `mod` / `use` / `pub` / crate とモジュールツリー

## 【パラダイム層】複数言語が共有する概念

| ID | パラダイム | Rust 対応 | JS との差分 | メモ |
|---|---|---|---|---|
| P1 | オブジェクト指向 | | | 継承が無く trait による合成である点 |
| P2 | 関数型 | | | `Iterator` の遅延評価、`map` / `filter` / `fold` |
| P3 | 非同期・並行 | | | `async` / `.await` はランタイム（tokio 等）が別途必要 |

## 【言語固有層】Rust 特有の概念

| ID | 概念 | 内容 | JS との違い | 理解度 |
|---|---|---|---|---|
| S1 | 所有権（ownership） | | GC が無く、スコープ終端で drop される | |
| S2 | 借用と参照（`&` / `&mut`） | | 可変参照は同時に1つだけ | |
| S3 | ライフタイム（`'a`） | | 参照の有効期間をコンパイラが検証 | |
| S4 | `Option` / `Result` | | `null` / 例外が無く、型で表現する | |
| S5 | trait とジェネリクス | | 構造的型付けではなく明示的な trait 実装 | |
| S6 | パターンマッチ（`match`） | | 網羅性をコンパイラが検査 | |
| S7 | `Box` / `Rc` / `RefCell` | | 所有の形を型で選ぶ（ヒープ / 共有 / 内部可変性） | |
| S8 | マクロ（`println!` 等の `!`） | | コンパイル時にコードを生成 | |
