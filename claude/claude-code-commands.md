# Claude Code コマンド整理 — トークン・コンテキスト効率と開発効率

対象バージョン: Claude Code 2.1.226

## 結論(まずこれだけ)

| 場面 | やること | 理由 |
|---|---|---|
| タスクを切り替える | `/clear` | 前のタスクの文脈を毎ターン再送しなくなる。**一番効くコスト削減** |
| 同じタスクが長引いた | `/compact` | 会話を要約して圧縮。文脈は残る |
| 今どれくらい使ってる? | `/context` | コンテキスト消費の内訳を可視化 |
| 何か調べたい・探したい | サブエージェントに任せる | 検索の中間結果が親の文脈に残らない |
| 大きな変更を始める前 | Plan モード(`Shift+Tab`) | 実装前に方針を確定させ、手戻り=無駄トークンを防ぐ |

---

## 1. コンテキスト管理系(資源効率の本丸)

### `/clear`
会話履歴を全部捨てて新規セッション相当にする。

- コンテキストは**毎ターン全部が再送される**ため、不要な履歴を抱えたまま作業を続けると1ターンあたりの単価がずっと上がり続ける
- 「別のタスクに移る」タイミングでは、迷わず `/clear`
- ただしプロンプトキャッシュも捨てることになるので、**同じタスクの途中で連打するのは逆効果**

### `/compact`
履歴を要約して圧縮する。文脈は保ったままトークンを減らせる。

- 要約の生成自体にトークンを消費するので、`/clear` で済むなら `/clear` の方が安い
- 使いどころは「同じタスクなのに会話が長くなりすぎた」とき
- コンテキストが上限に近づくと自動 compact も走る(`--autocompact` で発動サイズを調整可能)

### `/context`
現在のコンテキスト使用量を、システムプロンプト / CLAUDE.md / ツール定義 / 会話履歴といった内訳で表示。

- 「何が容量を食っているか」が分かるので、`/clear` すべきか CLAUDE.md を削るべきか判断できる

### `/resume` / `--continue`
- `/resume`(CLI では `claude -r`): 過去セッションを一覧から選んで再開
- `claude -c`: そのディレクトリの直近の会話を再開
- **再開は履歴を全部読み直す**ので、続きをやるなら有用、別件なら新規起動が安い

### `/rewind`(`Esc` 2回)
チェックポイントまで巻き戻す。コードの変更も会話も戻せる。

- 「間違った方向に進んだ」ときの復旧手段。誤った出力を土台にさらに会話を重ねるより圧倒的に安い

## 2. モデル・思考量のコントロール

### `/model`
使用モデルを切り替える。

- 定型的な修正・機械的な作業 → 軽いモデルで十分
- 設計・デバッグ・広い調査 → 上位モデル
- 「常に最上位」はコスト的にも速度的にも損。**タスクの難易度に合わせる**のが効率化の基本

### `--effort` (low / medium / high / xhigh / max)
思考にどれだけトークンを使うかのレベル。

- 難しい問題ほど上げる。単純作業で `max` は無駄

### `/fast`
Opus を高速出力モードで動かす(モデル自体は下がらない)。対話的な試行錯誤で効く。

### Plan モード(`Shift+Tab` で切り替え)
実装せず、まず計画だけ立てさせるモード。

- 実装 → 違う → やり直し、が一番トークンを溶かす。**計画を先に固めるのが最大の節約**
- 変更範囲が広いタスクでは常にこれから始める

### 自動承認モード(`Shift+Tab` でトグル)
毎回の許可プロンプトを省く。細かい確認の往復が減る。

- 破壊的操作のリスクは上がるので、Git 管理下+作業ブランチが前提

## 3. 開発効率系

### `/init`
リポジトリを解析して `CLAUDE.md` を生成する。

- `CLAUDE.md` は**毎セッション必ず読み込まれる**。ビルドコマンド・規約・ディレクトリ構成など「毎回説明していること」を書いておくと、以後の説明が丸ごと不要になる
- 逆に、肥大化させると全セッションで課金される固定費になる。**簡潔さが正義**

### `/memory`
CLAUDE.md 等のメモリファイルを編集する。同じ指示を繰り返している自分に気づいたら、ここに書いて恒久化する。

※ 2.1.226 では入力モードは通常入力とシェルモード(`!`)のみで、`#` プレフィックスによるメモリ追記は使えない。メモリは `/memory` かファイル直接編集で管理する。

### `@` プレフィックス
`@path/to/file` でファイルを明示的に参照。探索させるより速く、無駄な検索が減る。

### `!` プレフィックス
`!git status` のようにシェルコマンドを直接実行し、出力を会話に取り込む。
`gcloud auth login` のような対話的コマンドを自分で実行させたいときにも使う。

### カスタムスラッシュコマンド / Skill
`.claude/commands/*.md` や `.claude/skills/` に定型手順を置くと `/name` で呼べる。

- 「毎回同じ長いプロンプトを打つ」状態を解消できる = 入力トークンと手間の両方を削減

### サブエージェント(`/agents` で管理)
別コンテキストで作業させ、**結論だけ**が親の会話に返る。

- 「どのファイルに実装があるか探す」「広範囲を調べる」系は、これに任せると親のコンテキストが汚れない
- 逆に、既にファイルが分かっている単発調査は直接読んだ方が安い

### `/code-review`, `claude ultrareview`
現在の差分をレビュー。`--fix` で修正適用、`--comment` で PR にインラインコメント。

### `/security-review`
ブランチの変更に対するセキュリティレビュー。

## 4. 設定・環境系

| コマンド | 用途 |
|---|---|
| `/config` | テーマ・モデルなど各種設定 |
| `/permissions` | ツール許可ルールの編集(許可プロンプトの削減) |
| `/hooks` | ツール実行前後の自動処理を設定 |
| `/mcp` | MCP サーバの管理 |
| `/memory` | CLAUDE.md 等メモリファイルの編集 |
| `/doctor` | インストール・設定の健全性チェック |
| `/login`, `/logout` | 認証。`Login expired` が出たら `/login` |
| `/usage`, `/cost` | 使用量・コストの確認 |
| `/export` | 会話のエクスポート |
| `/help` | コマンド一覧 |

**注意**: MCP サーバやツールを増やすとツール定義がコンテキストを占有する。`/context` で確認し、使っていないものは外す。

## 5. CLI フラグ(起動時)

```bash
claude                      # 対話セッション開始
claude -c                   # 直近の会話を再開
claude -r                   # セッションを選んで再開
claude -p "prompt"          # 非対話実行(スクリプト・パイプ向け)
claude --model <model>      # モデル指定で起動
claude --effort high        # 思考レベル指定
claude -w <name>            # git worktree を作ってそこで作業
claude --add-dir <dir>      # 作業ディレクトリ外へのアクセスを許可
claude --safe-mode          # 全カスタマイズを無効化(設定壊れの切り分け用)
claude --bare               # フック・CLAUDE.md 自動読込等を全部スキップ(最小構成)
claude doctor               # インストール診断
claude update               # アップデート
```

- `-p` は CI やシェルパイプで使う。対話履歴を持たないので**最も軽い**
- `--bare` は CLAUDE.md も読まないため、固定費ゼロで単発作業したいときに有効

## 6. トークンを溶かすアンチパターン

| やりがち | 何が起きるか | 代わりに |
|---|---|---|
| 1セッションで何タスクもこなす | 無関係な履歴を毎ターン再送 | タスク単位で `/clear` |
| 巨大ファイルを丸ごと読ませる | 数万トークンが履歴に居座る | 該当箇所を `@file` + 行範囲、または grep |
| CLAUDE.md に何でも書く | 全セッションの固定費が増える | 「毎回必要な情報」だけに絞る |
| 計画なしで大きな実装を始める | 手戻りで全部やり直し | Plan モードで方針確定 |
| 詰まったまま会話を続ける | 誤った文脈の上に積み上がる | `/rewind` または `/clear` してやり直す |
| MCP を入れっぱなし | ツール定義でコンテキストを消費 | `/context` で確認して整理 |
| 同じ長い指示を毎回打つ | 入力トークンの無駄 | カスタムコマンド or `#` でメモリ化 |

## 7. 実践フロー例

```
1. claude              # プロジェクトルートで起動(CLAUDE.md が自動で読まれる)
2. Shift+Tab           # Plan モードへ。方針を固める
3. Shift+Tab           # 実装モードへ戻して実行
4. /context            # 消費が膨らんできたら確認
5. /compact            # 同じタスク継続なら圧縮
6. /code-review        # 差分をレビュー
7. /clear              # 次のタスクへ
```

## 覚え方

> **文脈は資産ではなくコスト。** タスクが変わったら捨てる(`/clear`)、
> 変わらないなら圧縮する(`/compact`)、増える前に測る(`/context`)。
